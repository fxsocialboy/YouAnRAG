# 阶段五收口说明：Query Analyzer / Rewrite / Multi-Query / HyDE

## 1. 收口结论

阶段五可以收口。当前项目已经在阶段四 `Qdrant dense + BM25 sparse + RRF + Cross-Encoder rerank + MMR` 基础上，新增 Query Planning 层，实现了 Query Analyzer、规则 Query Rewrite、Branch-aware Multi-Query 和条件 HyDE。

阶段五的核心不是默认开启 HyDE，而是根据 query 类型自适应选择检索策略：

```text
精确条款 / 年份 / 响应等级 query：保守，保留 raw query，不启用激进 rewrite / HyDE
场景处置 / 口语 query：启用 rewrite / multi-query，可选 HyDE
HyDE：只作为 dense-only 召回分支，不进入 evidence/citation
```

## 3. DeepSeek 真实验证

已完成真实 DeepSeek API 调用验证：

```text
query: 台风黄色预警下学校应该怎么做
mode: deepseek
reason: deepseek_hyde
used: true
```

生成的 HyDE 文本能够进入 `query_branches` 的 `hyde` 分支，权重为 `0.6`。端到端检索中，Top1 命中：

```text
深圳市气象灾害应急预案.md::258
section: （三）台风黄色预警信号
```

该 chunk 包含中小学停课、学生就近避险、学校妥善安置学生等内容，结果合理。

同时，HyDE 文本没有进入 `packed_context.evidence_chunks`，metadata 中 HyDE query 被隐藏为：

```text
<hyde_document>
```

避免将 LLM 生成内容作为 citation 证据。

## 7. 面试表述

> 在完成 dense+sparse 混合召回、Cross-Encoder 精排和 MMR 之后，我进一步实现了 Query Planning 层。系统会先用 QueryAnalyzer 判断用户问题属于精确条款、事实查询、场景处置还是短 query，再决定是否启用 rewrite、multi-query 和 HyDE。规则 Rewriter 会保留 raw query，同时生成 normalized 和 expanded 分支；Multi-Query Pipeline 对不同 branch 独立检索，并用 branch-aware RRF 融合重复 chunk。HyDE 支持 disabled、rule 和 DeepSeek 三种模式，但只作为 dense-only 召回分支，禁止进入 evidence/citation。为了防止改写破坏精确检索，我还设计了 guardrail_no_regression 指标，保证条款类 query 相比 Stage4 不退化。
