## 6. 阅读建议

### 建议重点阅读

1. `service.py`：阶段六总编排入口，也是面试最容易被追问的代码；
2. `models.py`：理解检索结果如何转成 Evidence、Citation 和最终 RagAnswer；
3. `verifier.py` 与 `guardrail.py`：理解“引用有效”和“证据足够”是两个独立判断；
4. `legacy_adapter.py`：理解独立 RAG 如何以低风险方式接回原 R Agent。

### 了解即可

- `evidence.py`、`composer.py`：读核心排序、编号和模板答案逻辑；
- `api.py`、`answer_stage6.py`：工程入口，不必逐行阅读；
- `evaluate_stage6.py`、报告生成脚本：知道验证了什么即可。

## 7. 面试回答

> 在完成 Qdrant 与 BM25 混合召回、Cross-Encoder 精排、MMR、Query Rewrite、Multi-Query 和条件 HyDE 后，我把检索链路进一步封装成了 Agentic RAG 服务。服务定义了 Evidence、Citation、RagAnswer 和 Trace 数据合同，对召回证据进行稳定编号，并生成带 `[S1]`、`[S2]` 引用的结构化答案；随后通过 Citation Verifier 检测不存在或缺失的引用，再通过 Guardrail 对空证据和低相关证据执行降级。工程上同时提供 Python API、CLI、FastAPI，以及兼容旧 `RAG.invoke()` 的 adapter，因此不修改原多智能体项目也能独立演示，未来可以渐进接回 R Agent。
