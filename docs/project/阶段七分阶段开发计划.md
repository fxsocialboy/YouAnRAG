# 阶段七分阶段开发计划：真实集成、最终评测与简历化收口

## 1. 阶段定位

阶段七是整个 RAG 优化项目的最后一个阶段。最高优先级不是继续增加缓存、并发、监控等生产工程，而是完成两个不可妥协的目标：

1. **真实替换**：优化后的 V2 RAG 必须真正进入原 `DisasterResponseAgent` 的 LangGraph，能够替代原 FAISS-only RAG 完成检索、方案生成、评审和最终输出，而不只是存在一个未被调用的 adapter；
2. **真实评测**：必须在 AutoDL GPU 上使用真实 BGE、Qdrant、BM25、Cross-Encoder、MMR 和 DeepSeek，对冻结标注集及大规模随机输入集运行完整评测，输出可解释、可复现、不过度包装的指标。

阶段 0~6 已经完成以下能力，阶段七不重复开发：

```text

→ Qdrant Local + SQLite 增量同步
→ BGE Dense + BM25 Sparse 粗排
→ RRF 融合
→ Cross-Encoder 精排
→ MMR 去冗余
→ Context Packing
→ Query Analyzer / Rewrite / Multi-Query / 条件 HyDE
→ Evidence / Citation / Verifier / Guardrail
```

阶段七负责把它们连接成最终可运行、可测量、可写进简历的完整系统。

## 3. 7.1 最终评测合同与双评测集冻结（✅ 已完成）

### 目标

在开发最终评测脚本前冻结数据、分组和指标，避免根据结果反向筛选问题。

### 3.1 标注质量集

构造 20~30 条有人工标签的质量集，用于计算可验证的检索指标：

- 从阶段五 `scenario`、`short_ambiguous`、`exact_guardrail` 三组中各选择 5~6 条；
- 增加 2~3 条 BM25 关键词问题；
- 增加 2~3 条知识库外问题；
- 增加 1~2 条需要综合多段/多文档的 query；
- 总规模控制在 25 条左右。

每条包含：

```json
{
  "query_id": "final_001",
  "query": "台风黄色预警下学校应该怎么做",
  "query_type": "scenario",
  "disaster_type": "meteorological",
  "relevant_source_files": ["深圳市气象灾害应急预案.md"],
  "relevant_chunk_ids": ["深圳市气象灾害应急预案.md::258"],
  "reference_facts": ["学校应采取停课或避险措施", "妥善安置在校学生"],
  "expected_fallback": false
}
```

`reference_facts` 只写 3~5 个答案必须包含的事实要点，不要求写长篇标准答案。

### 3.2 大规模随机鲁棒性集

额外生成并冻结 120 条随机自然语言输入，不读取参考答案、不从文档原文复制句子，使用固定随机种子和固定分组：

| 分组 | 数量 | 目的 |
|---|---:|---|
| 应急场景处置 | 40 | 验证常见自然语言场景 |
| 条款/关键词/责任主体 | 25 | 验证精确检索与 BM25 |
| 短句、口语、错别字、模糊表达 | 20 | 验证 Rewrite/Multi-Query 鲁棒性 |
| 跨文档或多条件问题 | 15 | 验证多路召回和上下文组装 |
| 知识库外问题 | 20 | 验证拒答和 fallback |

这 120 条不计算无标签的 Recall/MRR，只计算运行成功率、回答率、fallback 分布、引用映射、LLM-as-Judge 质量和延迟，并按分组展示结果。

### 3.3 指标定义

**标注质量集——检索指标：**

- `doc_recall@5/10`；
- `chunk_recall@5/10`；
- `doc_mrr@10`、`chunk_mrr@10`；
- `nDCG@10`；
- 端到端平均延迟、P50、P95。

**答案质量指标：**

- `faithfulness`；
- `answer_relevancy`；
- `citation_correctness`；
- `citation_completeness`；
- `fallback_accuracy`（只在有 fallback 标签的数据上计算）；
- `all_citations_mapped_ratio`；
- `answer_success_rate`、`error_rate`。

### faithfulness 的前提

模板答案直接抽取 evidence 原文，faithfulness 构造性接近 100%，不能代表真实生成质量。因此：

- `faithfulness` 和 `answer_relevancy` 只对 `composer_mode=deepseek` 的答案作为主要指标；
- template 模式只验证 citation mapping、citation completeness、fallback 和降级行为；
- 报告必须记录 `composer_mode`，不能混合两种模式后给出一个总分。

### 指标解释与目标区间

- 运行成功率目标 `>=95%`；
- 非 fallback 答案引用可映射率目标 `100%`；
- 未知引用数量目标 `0`；
- DeepSeek 答案平均 faithfulness 期望 `>=0.80`；
- 平均 answer relevancy 期望 `>=0.75`；
- OOD fallback accuracy 期望 `>=0.80`。

如果未达到期望，保留原始结果并做错误分类，而不是删除困难 query。知识库只有 51 份文档，随机输入出现无法召回或降级是合理边界，报告应说明“覆盖不足”而不是包装为模型错误。
