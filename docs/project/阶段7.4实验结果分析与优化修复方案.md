## 4. 逐条结果揭示的关键事实

### 4.1 OOD 并非都在胡乱回答，而是“语义拒答未结构化”

例如以下问题：

```text
怎么给 Transformer 模型设计稀疏注意力算子？
如何制作正宗法式可颂？
Java 虚拟机的垃圾回收器怎么选？
解释一下蛋白质折叠预测原理。
```

DeepSeek 实际输出均类似：

```text
现有证据不足，证据均为自然灾害资料，未包含该问题所需内容，因此无法回答。
```

这类回答在语义上已经是合理拒答，但 `RagAnswer.fallback_reason` 仍为 `None`，于是：

- `is_fallback=False`；
- OOD fallback accuracy 被记为失败；
- 这类拒答还被送给 Answer Judge；
- 因为没有回答原问题，Answer Relevancy 接近 0；
- 最终拉低随机集整体 Relevancy 和 Citation Completeness。

所以 `5%` 并不等同于“95% OOD 都产生了危险幻觉”，更准确的结论是：**系统缺少显式、结构化的 answer/fallback 决策协议**。

### 4.2 知识库内正确答案被引用正则误杀

标注集误 fallback 的四条为：

- `final_006`：气象灾害应急响应命令一般由谁签发；
- `final_014`：IV 级应急响应命令、副局长签发；
- `final_019`：自然灾害情况统计调查制度、统计法第七条；
- `final_020`：广东省自然灾害救助组织指挥体系。

其中 `final_006` 和 `final_014` 的草稿已经检索到正确文档，并明确输出：

```text
Ⅳ级和Ⅲ级应急响应命令由副局长签发，Ⅱ级和Ⅰ级由局长签发 [S1]
```

证据 Cross-Encoder 分数接近 `0.999`，答案中的核心事实也带有引用，但最终仍被替换为：

```text
当前知识库没有足够依据回答该问题。
```

根因在 `verifier.py`：

```python
FACT_RE = re.compile(...|一?级|...)
```

`一?级` 中的“一”是可选项，因此该表达式不仅匹配“一级”，还会匹配任意单独出现的“级”。只要某一行出现“级别”等普通文字且该行没有引用，就可能触发 `key_fact_without_citation`。

此外，正则还把任意数字视为关键事实。比如 OOD 问题中的“4K 视频”也会被识别为需要政策引用的数字事实。该规则把“是否存在关键事实”与“该事实是否来自知识库”混为一谈。

### 4.3 当前证据阈值实际上失效

`EvidenceGuardrail` 使用：

```python
max_score = max(item.score for item in evidence)
max_score < min_score
```

但 `EvidenceBuilder` 的 `item.score` 取以下分数中的最大值：

```text
MMR score
rerank score
fusion score
```

MMR 内部会把候选相关性在当前候选集合中做 min-max 归一化，因此第一名通常固定得到：

```text
mmr_score = 1.0
```

这意味着即使 OOD 查询的真实 Cross-Encoder 分数只有：

```text
0.0001、0.0034、0.0112
```

最终 `EvidenceItem.score` 仍可能为 `1.0`。`min_evidence_score=0.3` 因而几乎永远不会触发。

这是当前 OOD 漏拒答最关键的确定性代码缺陷：

> 排序用的相对 MMR 分数被错误地当成了可跨 query 比较的证据置信度。

### 4.4 Cross-Encoder 分数能提供有效信号，但不能单独解决全部 OOD

修复前结果中的最大 rerank score 分布：

| 数据组 | 最小值 | 中位数 | 最大值 |
|---|---:|---:|---:|
| 23 条标注集可回答问题 | 0.9876 | 0.9985 | 0.9999 |
| 100 条随机 in-domain | 0.4983 | 0.9709 | 0.9989 |
| 20 条随机 OOD | 0.0000 | 0.0140 | 0.8549 |

若仅使用最大 rerank score 阈值：

| 阈值 | OOD 拒答率 | 随机 in-domain 误拒答率 | 标注集误拒答率 |
|---:|---:|---:|---:|
| 0.10 | 65% | 0% | 0% |
| 0.20 | 80% | 0% | 0% |
| 0.40 | 85% | 0% | 0% |
| 0.50 | 85% | 1% | 0% |

因此，Cross-Encoder 阈值是有效的一层，但仍有 `新能源汽车股票`、`黑洞信息悖论`、`蛋白质折叠` 等问题因词面偶合得到较高分。不能只把阈值调高后宣称解决问题，需要加入领域判定和结构化 LLM 决策。

### 4.5 QueryAnalyzer 没有真正识别 OOD

当前所有 OOD query 都被归为默认 `scenario`，典型 trace 为：

```text
query_type = scenario
hazard_hint = None
extracted_terms = []
```

随后系统仍执行 Query Rewrite、Multi-Query、Dense/BM25、rerank 和 MMR，在 6269 个灾害 chunk 中总能找出相对第一名。这会造成“强制召回”：数据库一定返回结果，但返回结果不等于存在可回答证据。

当前 `QueryAnalyzer` 需要区分：

- 明确灾害/应急领域；
- 可能属于领域但表达模糊；
- 明确知识库外。

但领域判定不能简单使用 `hazard_hint is None`，因为“应急响应签发主体”“灾情怎么上报”等有效问题也可能没有具体灾种提示。

### 4.6 评测口径仍有三处需要修正

#### （1）随机集 Recall 显示为 0

随机集没有 `relevant_source_files/relevant_chunk_ids`，所以 Recall 应报告为 `N/A`，而不是数值 0。否则容易被误解为检索完全失败。

#### （2）V2 检索指标基于 Context Packing 后的 Evidence

Legacy 使用原始 Top-10，V2 当前从最终 packed evidence 反推排名。Context Packing 会合并相邻 chunk、受 token budget 限制，因此不是严格的同口径原始 Top-10 对比。

后续应同时保存：

- `raw_retrieval_results`：用于 Recall/MRR/nDCG；
- `packed_evidence`：用于答案生成和引用指标。

这样 Legacy 与 V2 的检索指标才是严格可解释的，而上下文组装效果另行统计。

#### （3）延迟混入离线 Judge 时间

当前答案 `latency_ms` 等于：

```text
在线 RAG 回答耗时 + 离线 DeepSeek Judge 耗时
```

面试中应报告用户实际等待的在线延迟，Judge 只是评测成本。后续报告要拆分：

- retrieval latency；
- composer/online answer latency；
- judge latency；
- evaluation total latency。

## 6. 总体修复架构

修复后的决策链路设计为：

```text
Query
  ↓
Domain Gate（明确 OOD / 明确 in-domain / uncertain）
  ↓
Query Analyze + Rewrite + Multi-Query + 条件 HyDE
  ↓
Qdrant Dense + BM25 + RRF
  ↓
Cross-Encoder rerank
  ↓
Evidence Confidence（保留原始 rerank/dense/fusion，不使用 MMR 相对分数）
  ↓
MMR 只负责多样性选择
  ↓
Context Packing
  ↓
DeepSeek Composer 输出结构化 decision + answer
  ↓
CitationVerifier 只校验引用结构
  ↓
Answer Sufficiency Gate
  ↓
RagAnswer(status=answered/fallback, reason=...)
```

核心原则：

1. **相关性、排序、多样性三个分数职责分离**；
2. fallback 是显式状态，不依赖自然语言中是否恰好出现某句话；
3. 引用校验失败不应一律销毁整个正确答案；
4. OOD 判定采用规则、模型分数和 LLM decision 的分层组合；
5. 所有决策信号进入 trace，便于面试解释和错误分析。

## 7.2 阶段7.4.2：修复证据分数与CitationVerifier

### 目标

合并原R2和R3，一次解决两个确定性代码缺陷：MMR相对分数被错误作为证据置信度，以及CitationVerifier误杀正确答案。

### 开发内容A：分离分数语义

明确区分：

```text
rerank_score           # Cross-Encoder原始相关性
fusion_score           # RRF融合排序分数
mmr_score              # 多样性选择分数，只用于选择和解释
sort_score             # 最终显示/排序辅助值
retrieval_confidence   # Guardrail唯一使用的证据置信度
```

规则如下：

1. 有`rerank_score`时，`retrieval_confidence`使用原始Cross-Encoder分数；
2. 无reranker但有dense score时，使用明确标注来源的dense置信信号；
3. 只有RRF时，不把RRF小数包装成概率，使用独立阈值或标记`confidence_unavailable`；
4. MMR继续执行多样性选择，但不能覆盖`retrieval_confidence`；
5. Context Packer合并邻接chunk时保留seed chunk的真实相关性和分数来源；
6. trace记录`confidence_type`、`confidence_value`、阈值和触发原因。

初始使用保守三段策略：

```text
max_rerank_score < 0.20       → low_confidence
0.20 <= score < 0.50          → uncertain
score >= 0.50                 → retrieval_confident
```

该阈值只是初始校准信号，不单独承担全部OOD判断。

### 开发内容B：修复CitationVerifier

1. 删除错误表达式`一?级`，使用明确响应等级枚举；
2. 不再把任意数字都视为必须引用的政策事实；
3. 跳过Markdown标题、纯列表编号和结构性文本；
4. 区分硬失败和软告警：

```text
missing_citation          # 硬失败
citation_without_evidence # 硬失败
evidence_without_citation # 诊断信息
key_fact_without_citation # 默认软告警
```

5. 对局部引用缺失可进行一次受限修复，只允许补充已有`[Sx]`，不得新增事实；
6. 保持未知引用为0和Citation到Evidence的严格映射。

### 必测样本

- `final_006`、`final_014`应从误fallback恢复为answered；
- `final_019`、`final_020`不再被宽泛正则直接清空；
- “级别不同”“4K视频”和列表编号不触发硬失败；
- 无引用的关键政策事实产生软告警；
- `[S99]`仍必须硬失败；
- OOD低rerank证据不再出现`retrieval_confidence=1.0`。

### 单元测试

- Evidence、Context Packer、MMR、Guardrail和Verifier定向测试；
- fake reranker覆盖有/无rerank两条路径；
- 4条标注集误fallback离线回放；
- 全量历史测试。

### 收敛标准

- 排序和MMR功能不回归；
- Guardrail不再读取MMR分数作为置信度；
- 4条标注集误fallback得到确定性修复；
- 未知引用仍为0；
- 不提前引入Domain Gate或结构化Composer，保证归因清晰。

### 是否需要GPU

单元测试与结果回放不需要；真实阈值验证留到7.4.5。

### 学习建议

这是面试价值较高的核心代码，建议重点阅读Evidence分数传递、MMR与相关性分离，以及Verifier硬失败/软告警设计。

## 7.3 阶段7.4.3：Domain Gate与结构化Fallback

### 目标

合并原R4和R5，在昂贵生成前增加领域覆盖判断，并解决“答案文字已经拒答，但`is_fallback=False`”的状态不一致问题。

### 开发内容A：三态Domain Gate

新增：

```text
in_domain
out_of_domain
uncertain
```

采用三层判断：

1. 透明领域规则：灾种、预警、响应、救援、疏散、避险、灾情、减灾、救助、指挥体系、预案、风险普查、响应等级和条款结构；
2. 检索后置信度：使用7.4.2修复后的Cross-Encoder/检索置信度；
3. 结构化LLM覆盖判定：仅对`uncertain`或高分但无领域信号的query调用DeepSeek，根据query和evidence判断知识库是否可回答。

不能简单使用`hazard_hint is None`判OOD，因为“四级响应到底谁开”“灾情怎么上报”等问题仍属于领域内。

### 开发内容B：结构化Composer决策

DeepSeek Composer改为JSON协议：

```json
{
  "decision": "answered | fallback",
  "answer": "最终中文回答",
  "fallback_reason": "out_of_domain | insufficient_evidence | null",
  "used_citation_ids": ["S1", "S2"]
}
```

统一约束：

- `decision=fallback`时，`RagAnswer.fallback_reason`必须非空；
- `decision=answered`时必须至少使用一个有效citation；
- fallback答案不能统计为answered；
- JSON解析失败时回退模板并记录trace；
- 字符串“现有证据不足”只作为兼容兜底；
- “部分证据不足”不能把整个正常答案自动判为fallback。

Domain Gate和Composer决策均写入trace，包括decision、signals、confidence、decision source和fallback reason。

### Answer Judge调整

- fallback样本不计算Faithfulness和Citation Completeness；
- 单独统计fallback reason consistency；
- answered样本才计算答案质量；
- 报告Judge coverage。

### 单元测试

- fake DeepSeek的answered、fallback、非法JSON和超时路径；
- 20条OOD回归；
- 无明确灾种但属于应急领域的防误拒测试；
- 高rerank词面偶合OOD测试；
- fallback三项状态一致性测试；
- Legacy Adapter与原LangGraph接口回归。

### 收敛标准

- 当前19条语义拒答OOD能够结构化为fallback；
- OOD回归集fallback accuracy目标不低于0.80；
- in-domain回归集answer rate目标不低于0.85；
- 不能读取评测标签或硬编码query_id；
- 原YouAn Agent继续使用兼容的`RagAnswer`合同。

### 是否需要GPU

规则和fake LLM测试不需要；少量真实DeepSeek smoke需要联网；最终校准在AutoDL完成。

### 学习建议

这是7.4最核心的功能，重点理解三态Gate、规则/模型/LLM分层决策，以及为什么fallback必须是结构化业务状态。

## 12. 修复后的面试价值

完成本方案后，项目可以形成比单纯“接了向量数据库和reranker”更有价值的面试故事：

> 在最终真实评测中，我发现只依赖Top-K一定会为知识库外问题强制召回结果，同时MMR的相对归一化分数被误用为证据置信度，导致低相关证据无法触发降级；此外，规则式引用校验会误伤含“级别”和列表编号的正确答案。我基于170条真实结果建立失败回归集，将相关性、排序和多样性分数解耦，增加三态Domain Gate和结构化fallback协议，并严格区分原始检索、上下文组装、在线回答和离线Judge指标，最后在冻结数据上完成修复前后对比。

该表述包含：真实评测、问题定位、分数语义、OOD、Guardrail、结构化输出、可观测性和消融意识，适合作为后端开发或Agent/RAG开发方向的核心项目亮点。

## 13. 当前结论

当前项目的核心检索和生成链路已经成立，主要问题集中在最后一公里的**置信度判定、fallback状态和评测口径**，无需推翻阶段一至阶段七已经完成的架构。

下一步应从阶段7.4.1开始，在本地冻结基线并建立失败回归集，然后按五阶段顺序逐层修复。完成7.4.4和7.4.5本地收口前，不应再次启动AutoDL完整评测。
