# 阶段一分阶段开发计划：数据管道与索引正确性修复

## 0. 定位与原则

阶段一的目标不是做一个生产级 ingestion 平台，而是快速修复当前 RAG 最影响效果的底层问题，并形成能写进简历、能通过 baseline 量化对比的优化成果。

当前阶段一应聚焦 6 个核心问题：

1. `clean_markdown` 删除所有空白，导致英文粘连、标题/列表/条款结构消失；
2. 存在 67K 字符巨块，embedding 实际只编码开头，检索后却可能把完整巨块塞给 LLM；
3. 分块没有 overlap，语义容易被切断；
4. Markdown 标题路径没有进入 embedding，chunk 缺少章节上下文；
5. BGE instruction 使用方向不合理：旧索引 passage 加 instruction，在线 query 不加；
6. chunk metadata 太弱，检索结果难以展示来源文件、章节和可调试信息。

因此阶段一采用“够用但不重”的实现策略：

- 不做 Parent/Child 双层分块；
- 不做复杂 Section Tree 和 DocumentBlock 数据类体系；
- 不做表格、公式、参考文献专用解析器；
- 不做 7~8 组大规模消融实验；
- 不做 UUID5 稳定 chunk id；
- 第一版仍重建 FAISS 索引，Qdrant 自动更新放到后续阶段。

核心实现只保留：

```text
Markdown 文件
→ 保守清洗
→ 标题路径解析
→ 正文块聚合
→ Token 分块 + overlap + hard max
→ embedding_text = 标题路径 + 正文
→ BGE 重新编码
→ 新 faiss_index.index + chunk_metadata.json
→ 运行 baseline 对比
```

### 目标

替代 legacy 中破坏结构的：

```python

```

### 开发内容

```text

```

保守清洗规则：

1. 统一换行符为 `\n`；
2. `html.unescape` 处理 `&amp;`、`&lt;`；
3. 删除不可见控制字符；
4. 英文单词之间保留一个空格；
5. 中文段落、标题、列表换行保留；

7. 不删除条款号、罗马数字、预警颜色、响应等级。

### 单元测试样例

- `## 4 应急响应` 清洗后标题标记仍存在；
- `（一）启动条件` 不被删除；
- `&amp;` 被转换为 `&`；
- 多余空行被压缩。

### 验收标准

- 英文不再粘连；
- Markdown 标题不丢失；
- 单测覆盖中英文混合、标题、列表、HTML entity。

## 4. 小阶段 1.3：Markdown 标题路径解析

### 目标

不引入复杂 Section Tree，只用栈维护当前标题路径，让每个正文段落知道自己属于哪个章节。

### 开发内容

新增：

```text
G:\tiaozhanbei\newrag\src\rag_v2\ingestion\markdown_parser.py
G:\tiaozhanbei\newrag\tests\test_markdown_parser.py
```

输出轻量 paragraph block：

```python
{
  "source_file": "深圳市气象灾害应急预案.md",
  "section_path": ["深圳市气象灾害应急预案", "4 应急响应", "4.4 分灾种响应"],
  "text": "气象部门加强监测预报……",
  "block_type": "paragraph" | "heading" | "list" | "toc" | "reference",
  "is_indexable": True
}
```

识别规则：

- `# / ## / ### / ####` 更新标题路径；
- 没有标题的文件，默认用文件名作为一级标题；
- 短目录行、纯页码行、参考文献标题后的大量文献条目可以标记为 `is_indexable=False`；
- 只做轻量判定，不做复杂 PDF 版面恢复。

### 单元测试

- 标题层级栈正确更新；
- 从 `##` 跳到 `###` 时能继承父标题；
- 新的同级标题会替换旧同级标题；
- 正文 block 能拿到完整 `section_path`；
- 目录/参考文献样例能被标记为不可索引。

### 验收标准

- 解析 51 份 Markdown 不报错；
- 至少 90% 以上可索引 block 有非空 `section_path`；
- 不把目录和参考文献作为核心检索内容。

## 5. 小阶段 1.4：Token 分块 + overlap + hard max

### 目标

消除 67K 巨块，保证所有进入 embedding 的文本都受 token 上限控制，并通过 overlap 降低语义切割风险。

### 开发内容

新增：

```text
G:\tiaozhanbei\newrag\src\rag_v2\ingestion\token_counter.py
G:\tiaozhanbei\newrag\src\rag_v2\ingestion\chunker.py
G:\tiaozhanbei\newrag\tests\test_chunker.py
```

第一版固定参数，不做大规模网格搜索：

```text
target_tokens = 280
soft_max_tokens = 360
hard_max_tokens = 448
overlap_tokens = 50
min_tokens = 40
```

分块策略：

1. 同一 `section_path` 内累积段落；
2. 优先在句号、分号、换行处切分；
3. 超过 `soft_max_tokens` 后必须截断当前 chunk；
4. 单段超过 `hard_max_tokens` 时按 token 边界硬切；
5. overlap 不跨章节；
6. 过短尾块尽量并入前一块；
7. `chunk_id` 使用：

```text
{source_file}::{chunk_index}
```

### 单元测试

- 构造 1000 token 超长段落，必须被切成多个不超过 hard max 的 chunk；
- overlap 约为 50 token，且不跨 section；
- chunk_index 从 0 递增；
- 空内容、不可索引 block 不生成可索引 chunk；
- section_path 能进入 chunk metadata。

### 验收标准

- 不存在超过 `hard_max_tokens` 的可索引 chunk；
- 67K 字符巨块消失；
- chunk 数量相对 legacy 允许变化，但不应少于 legacy 的 50%，不应超过 legacy 的 3 倍；
- `section_path` 缺失比例低于 10%。
